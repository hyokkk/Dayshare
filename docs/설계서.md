## 1. 앱 개요

### 앱 이름

**dayshare**

> v3.1에서 가칭 Together Calendar에서 변경. 앱 이름은 화면 문구와 HTML 제목에만 쓰이며 DB에는 저장되지 않는다.
> 기기에 저장하는 로그인 키(`tc:me:v2`)는 이름 변경과 무관하게 유지한다. 바꾸면 모든 사용자의 로그인이 풀린다.

### 목적

친구, 가족, 연인 등 여러 명이 하나의 그룹에 참여하여 각자의 일정을 등록하고, 모든 구성원의 일정을 하나의 캘린더에서 확인할 수 있는 공유 캘린더 앱을 만든다.

### 핵심 가치

* 여러 사람의 일정을 한 화면에서 확인
* 누가 어떤 일정을 등록했는지 쉽게 구분
* 그룹 코드만으로 간편하게 공유
* 복잡한 기능을 제외하고 일정 공유에 집중

### 주요 사용자

가족 / 친구 모임 / 커플 / 여행 그룹 / 소규모 팀

## 2. MVP 핵심 기능

### 2.1 그룹

사용자는 여러 개의 그룹을 만들거나 참여할 수 있다.

* 그룹 생성 및 그룹 이름 설정
* 그룹 코드 자동 생성
* 그룹 코드 입력 또는 **초대 링크**를 통한 그룹 참여 **[v3]**
* 그룹별 캘린더 제공
* 그룹 멤버 목록 확인
* 달력 화면 상단에서 그룹 간 전환
* **그룹장 제도** (2.9절) **[v3]**

> **그룹 코드 생성 규칙**
> 6자리 영문 대문자 + 숫자 조합으로 자동 생성한다. 눈으로 혼동하기 쉬운 문자(`O` `0` `I` `1`)는 제외한다. 생성 시 중복 여부를 확인하고, 중복이면 다시 생성한다. 입력 시 소문자는 자동으로 대문자로 변환한다.

> **[v3] 새 그룹 생성 직후 동작**
> 새로 만든 그룹은 멤버가 본인뿐이므로, 달력 탭이 아니라 **그룹 탭(초대 화면)** 으로 연다.

---

### 2.2 사용자 **[v3]**

각 사용자는 닉네임과 프로필 색상을 설정한다.

* 닉네임 (최대 10자)
* 프로필 색상 (8색 팔레트 중 선택)

#### 계정과 복구 코드

비밀번호 대신 **개인 복구 코드**로 계정을 식별한다.

| 항목 | 내용 |
|---|---|
| 형식 | 8자리 영문 대문자 + 숫자, `ABCD-2345`처럼 4-4로 표시 |
| 문자 | 그룹 코드와 동일하게 `O` `0` `I` `1` 제외 |
| 생성 | 가입 시 암호학적 난수로 자동 생성 (중복 시 재생성) |
| 입력 | 하이픈/공백/소문자를 허용하고 내부에서 정규화 |
| 저장 | DB에는 하이픈 없이 저장 |

**흐름**

1. 처음 쓰는 사람: 이름/색상 입력 → 계정 생성 → **복구 코드 안내 화면**에서 저장을 권함
2. 다른 기기: 온보딩에서 "쓰던 계정이 있어요" → 복구 코드 입력 → 같은 계정으로 접속, 참여 중인 그룹이 그대로 보임
3. 복구 코드는 "내 정보"에서 언제든 다시 볼 수 있다
4. "이 기기에서 로그아웃" 시 복구 코드를 한 번 더 보여주고 확인을 받는다

> **복구 코드의 한계**
> 복구 코드를 잃어버리면 계정을 되찾을 방법이 없다. 반대로 코드를 아는 사람은 누구나 그 계정으로 들어올 수 있다. 가족/친구 등 신뢰 관계의 소규모 그룹을 전제로 한 방식이다.

> **로그인 방식 선택 근거**
> 아이디/비밀번호, 카카오 로그인, 개인 복구 코드 세 가지를 검토했다. 이메일 인증 방식은 Supabase 무료 메일 발송이 시간당 2통, 팀원 주소 한정이라 제외했다.
> 복구 코드는 추가 설정 없이 바로 쓸 수 있는 대신, 그룹장 권한 등이 **화면 단계에서만** 강제된다는 한계가 있다 (6장 참고). 향후 카카오 로그인으로 전환하면 DB 단계에서 권한을 강제할 수 있다.

> **색상 중복 처리**
> 그룹에 참여할 때 자신이 고른 색을 이미 다른 멤버가 쓰고 있으면, 그 그룹 안에서는 비어 있는 색이 자동 배정된다. 색상은 그룹별로 저장하므로 그룹마다 다를 수 있다.

> **프로필 수정**
> 닉네임을 바꾸면 모든 그룹에 반영된다. 색상은 해당 그룹의 다른 멤버와 겹치지 않는 그룹에만 반영된다.

### 2.3 일정 등록

필수 입력

* 일정 제목 (최대 40자)
* 날짜 (단일 날짜 또는 기간)
* 카테고리

선택 입력

* 시간대
* 장소 (최대 40자)
* 메모 (최대 200자)

**카테고리 (2종 유지)**

* 직장/업무
* 일상

> **[변경] 카테고리 확장 검토 결과**
> 회식 / 약속 / 여행 / 출장을 추가해 6종으로 확장하는 안을 검토했으나 철회했다.
> 사유: 카테고리가 6종이 되면 "색에 의존하지 않고 카테고리를 구분한다"는 원칙을 지키기 위해 텍스트 배지 같은 별도 표기가 필요해지고, 그 결과 달력 칩이 복잡해져 가독성이 떨어졌다. 2종 체계에서는 채움/옅음이라는 시각적 대비만으로 구분이 가능하다.

**시간대**

정확한 시각 대신 다음 중 하나를 선택한다.

* 오전 / 점심 / 오후 / 저녁 / 종일

**기간 일정**

시작일과 종료일을 지정한다. 종료일을 비우면 단일 날짜 일정으로 처리한다. 종료일이 시작일보다 빠르면 저장을 거부하고 안내한다.

**일정 유형**

* 개인 일정
* 공동 일정

일정을 등록하면 작성자가 자동으로 기록된다.

---

### 2.4 공동 일정

그룹 내 모든 멤버가 함께하는 일정.

* 그룹의 모든 멤버가 등록 / 수정 / 삭제 가능
* 개인 일정과 다른 전용 색상으로 표시
* 공동 일정의 작성자도 기록하며, 상세 화면에서 "전체 (등록: 홍길동)" 형태로 표시

### 2.5 일정 조회

기본 화면은 월간 캘린더다.

> **[변경] 날짜 선택 시 동작**
> v1에서는 달력 아래에 선택한 날짜의 일정 목록을 항상 표시했으나, 달력이 세로로 밀려 내려가는 문제가 있었다.
> v2에서는 날짜를 누르면 **그날의 일정만 보여주는 별도 화면**으로 이동한다.

**[추가] 월 이동 방법**

* 제목 옆 이전/다음 버튼
* 제목을 누르면 열리는 월 선택 시트 (연도 이동 + 12개월 선택 + "오늘로 이동")

**[추가] 목록 탭**

달력 대신 현재 보고 있는 달의 일정을 날짜순 목록으로 확인할 수 있는 탭을 추가한다.

* 날짜별로 묶어 표시
* 일정이 있는 날과 공휴일만 표시
* 달력 화면에서 적용한 필터가 그대로 반영됨

> **하루 내 일정 정렬 기준**
> 같은 날짜에 여러 일정이 있으면 시간대(오전 → 점심 → 오후 → 저녁 → 종일) 순으로 정렬한다. 시간대가 같으면 등록 순서를 따른다.

### 2.6 일정 필터 **[변경]**

#### 동작 방식

* 아무것도 선택하지 않은 상태가 기본이며, 이때 모든 일정이 표시된다
* 항목을 선택하면 그 조건에 맞는 일정만 표시된다
* 같은 그룹(줄) 안에서는 다중 선택 시 OR 조건
* 서로 다른 그룹 간에는 AND 조건
* 선택된 항목이 하나라도 있으면 "전체 보기" 버튼이 나타나 한 번에 해제할 수 있다

예시

```text
효경 + 민수          → 두 사람의 일정
효경 + 오전          → 효경의 오전 일정만
직장/업무 + 오전/점심 → 오전 또는 점심의 직장/업무 일정
```

#### 필터 종류

| 필터 | 항목 |
|---|---|
| 사용자 | 그룹 멤버 각각 + 공동 |
| 카테고리 | 직장/업무, 일상 |
| 시간대 **[추가]** | 오전, 점심, 오후, 저녁, 종일 |

#### 배치

필터는 달력 위에 항상 펼쳐진 상태로 노출한다. (숨김 방식 대비 조작 단계가 하나 줄어듦)

* 첫째 줄: 사용자 필터. 멤버 색상 점을 함께 표시하여 **범례 역할을 겸한다**
* 둘째 줄: 카테고리 필터 + 구분선 + 시간대 필터
* 우측 화살표 버튼으로 필터 영역 전체를 접고 펼 수 있다 (기본값: 펼침)

공휴일 데이터를 코드 안의 상수로 내장한다. 조회는 반드시 `getHoliday(date)` 함수 하나만 거치도록 하여, 데이터 출처를 바꿀 때 이 함수의 내부 구현만 교체하면 되게 한다.

**전환 후 (외부 빌더)**

npm 패키지 `@hyunbinseo/holidays-kr`로 교체한다.

| 항목 | 내용 |
|---|---|
| 원본 | 우주항공청 월력요항 (관보 게재) |
| 배포 형태 | npm 패키지 (ESM/CJS), 정적 json/csv/ics 파일 |
| 라이선스 | MIT |
| 서버 필요 여부 | 불필요 — 빌드 시 번들에 포함되므로 네트워크 요청, CORS, API 키가 모두 불필요 |
| 갱신 방법 | 연 1회 패키지 업데이트 |

**공공데이터포털 특일 정보 API를 쓰지 않는 이유**

* 서비스키가 필요하고, 비밀 키이므로 클라이언트 코드에 넣을 수 없다 → 별도의 서버(프록시)가 필수
* 브라우저에서 직접 호출하면 CORS로 차단된다
* 서버를 추가로 운영해야 할 만큼의 이점이 없다

**연도 범위의 한계 (모든 방식 공통)**

월력요항은 매년 전년도에 발표되므로, 어떤 출처를 쓰더라도 발표되지 않은 미래 연도의 데이터는 존재하지 않는다. 2026년 9월 기준으로 공식 확정된 범위는 2027년까지다. API를 연동해도 이 한계는 동일하다.

데이터에 없는 연도는 공휴일 없이 일반 날짜로 표시한다. (오류 처리 대상이 아님)

**명칭 표기 차이**

`holidays-kr`은 공휴일에 관한 법률의 명칭을 따른다. 앱에서는 달력 칩 가독성을 위해 일상적인 표기를 쓰고 있으므로, 전환 시 변환표가 필요하다.

| 법률 명칭 | 앱 표기 |
|---|---|
| 1월 1일 | 신정 |
| 3ㆍ1절 | 삼일절 |
| 설날 전날 / 설날 다음 날 | 설날 연휴 |
| 추석 전날 / 추석 다음 날 | 추석 연휴 |
| 기독탄신일 | 성탄절 |
| 대체공휴일(○○) | 대체공휴일 |

### 2.9 그룹장 **[v3]**

그룹을 만든 사람이 그룹장이 된다. 그룹당 한 명이다.

| 동작 | 그룹장 | 일반 멤버 |
|---|---|---|
| 멤버 내보내기 | ✅ | ❌ |
| 그룹장 넘기기 | ✅ | ❌ |
| **그룹 이름 변경** **[v3.1]** | ✅ | ❌ |
| **다른 멤버의 일정 대신 등록** **[v3.1]** | ✅ | ❌ |
| 그룹 나가기 | 다른 멤버가 없을 때만 (= 그룹 삭제) | ✅ |
| 그 밖의 일정 등록/수정/삭제 | 일반 규칙과 동일 | 일반 규칙과 동일 |

**규칙**

* 멤버를 내보내거나 멤버가 스스로 나가면, 그 멤버가 등록한 **개인 일정은 함께 삭제**한다
* **공동 일정은 그룹의 것이므로 남긴다** (등록자가 나가도 유지)
* 그룹장은 다른 멤버가 남아 있으면 나갈 수 없다. 먼저 다른 멤버에게 그룹장을 넘겨야 한다
* 그룹장이 혼자 남은 상태에서 나가면 **그룹이 삭제**된다. 이때 버튼 이름은 "그룹 삭제"로 표시한다
* 모든 삭제/넘기기는 확인 창을 거친다
* 내보내진 멤버가 앱을 다시 보면 "그룹에서 내보내졌습니다" 안내 후 그룹 화면에서 빠져나온다. 그룹이 삭제된 경우도 동일하게 처리한다

> **처리 위치**
> 위 규칙은 DB 함수(`remove_member`, `transfer_owner`)에서 한 번에(원자적으로) 처리한다. 화면에서 여러 번 나눠 호출하다 중간에 실패하는 상황을 막기 위함이다.

### 2.9.1 그룹 이름 변경 **[v3.1]**

* 그룹 탭의 이름 옆 "이름 변경" 버튼은 그룹장에게만 보인다
* 앞뒤 공백은 저장할 때 제거하고, 공백만 입력하면 거부한다
* 바뀐 이름은 다른 멤버가 앱을 다시 볼 때 자동으로 반영된다 (달력 상단 그룹 칩, 그룹 탭)
* 그룹 코드는 바뀌지 않는다. 이미 보낸 초대 링크도 그대로 쓸 수 있다

### 2.9.2 다른 멤버의 일정 대신 등록 **[v3.1]**

그룹장은 일정 입력 화면에서 "누구의 일정인가요?"로 멤버를 골라 대신 등록할 수 있다.
직접 앱을 쓰기 어려운 가족의 일정을 대신 넣는 상황을 위한 기능이다.

| 항목 | 처리 |
|---|---|
| 표시 | 고른 멤버의 이름/색으로 달력에 표시된다 (본인이 넣은 것과 똑같이 보인다) |
| 노출 조건 | 그룹장이면서, 개인 일정이면서, 멤버가 2명 이상일 때만 |
| 공동 일정 | 주인이 없으므로 담당자 선택을 숨긴다 |
| 기록 | 일정에 주인(`user_id`)과 등록한 사람(`created_by`)을 따로 남긴다 |
| 상세 화면 | 둘이 다르면 "민수 (효경님이 등록)"으로 표시한다 |

> **[v3.1] 수정/삭제 권한 확장**
> 대신 등록한 사람이 나중에 오타를 고칠 수 없으면 곤란하므로, 수정/삭제 권한에 "내가 등록한 일정"을 더한다.
>
> 공동 일정이거나, 내 일정이거나, 내가 등록한 일정이면 고칠 수 있다.
>
> 그룹장에게 그룹 내 모든 일정에 대한 수정 권한을 주는 방식도 검토했으나, 요청 범위를 넘어서므로 채택하지 않았다.

> **[v3.1] 내보내기와의 관계**
> 멤버를 내보내면 그 멤버의 개인 일정이 삭제되는데, 그룹장이 대신 등록해 준 일정도 그 멤버의 것이므로 함께 삭제된다.

### 2.10 초대 / 공유 **[v3]**

그룹 탭의 초대 카드에서 세 가지 방법을 제공한다.

| 버튼 | 동작 |
|---|---|
| 초대하기 | 휴대폰 기본 공유창을 연다. 카카오톡 등 설치된 앱을 고를 수 있다. 공유창을 지원하지 않는 환경에서는 초대 문구+링크를 복사한다 |
| 링크 복사 | 초대 링크만 복사 |
| 코드 복사 | 그룹 코드만 복사 |

**초대 링크 형식**: `https://사이트주소/?join=그룹코드`

**초대 링크로 들어온 사람의 흐름**

1. 링크를 열면 주소의 `?join=` 부분은 즉시 지운다 (새로고침 시 반복 방지)
2. 계정이 없으면: 온보딩에 "'우리 가족' 그룹에 초대받았어요"를 표시 → 가입 → 복구 코드 안내
3. 복구 코드 안내를 마친 뒤 "'우리 가족' 그룹에 참여할까요?" 확인
4. 이미 멤버면 확인 없이 바로 그 그룹을 연다
5. 그룹이 없어졌으면 "초대받은 그룹을 찾을 수 없습니다" 안내

> **카카오톡 전용 카드를 쓰지 않은 이유**
> 썸네일과 버튼이 있는 카카오톡 공유 카드는 카카오 개발자 앱 등록과 도메인 설정이 필요하다. 휴대폰 기본 공유창으로도 카카오톡에 링크를 보낼 수 있으므로, 추가 설정이 없는 방식을 택했다.

## 4. 디자인 및 UX **[변경]**

### 참고 모델

월간 캘린더 UI는 **TimeTree**의 구성을 참고한다.

### 캘린더 레이아웃 규칙

* **세로 격자선을 두지 않는다.** 주 구분선만 아주 옅게 표시
* **주 높이를 고정한다.** 일정 개수와 무관하게 일정한 높이를 유지하여 여백을 확보
* 날짜 숫자는 칸 위쪽 가운데 정렬, 작은 크기
* 오늘 날짜는 숫자를 원형으로 채워 표시
* 선택한 날짜는 해당 칸의 세로 전체를 연한 회색 띠로 표시
* 한 주에 표시 가능한 막대는 최대 3개이며, 넘치면 `+N`으로 표시
* **[추가]** 달력 영역을 좌우로 스와이프하면 이전/다음 달로 이동한다. 세로 스크롤과 충돌하지 않도록 가로 이동 거리가 세로보다 충분히 클 때만 반응한다. 월이 바뀔 때 이동 방향에 맞춰 짧게 밀려 들어오는 전환 효과를 준다

### 일정 칩 규칙

* 칸 폭을 거의 꽉 채우는 둥근 막대
* 텍스트는 가운데 정렬, 작고 굵게
* 넘치는 글자는 말줄임표 없이 잘림
* 기간 일정은 시작일부터 종료일까지 하나의 막대로 이어짐. 주를 넘어가면 다음 주 첫 칸부터 이어서 표시

### 색상 체계

| 대상 | 표현 |
|---|---|
| 개인 일정 | 작성자의 멤버 색상 |
| 공동 일정 | 전용 색상 (틸) |
| 직장/업무 | 해당 색상을 꽉 채우고 흰 글씨 |
| 일상 | 해당 색상의 파스텔 톤 배경 + 같은 색 글씨 |
| 공휴일/대체공휴일 | 진한 빨강 배경 + 흰 글씨 |
| 일요일 | 빨강 숫자 |
| 토요일 | 파랑 숫자 |

> **색의 의미 배분**
> 색(색상 계열)은 "누가 등록한 일정인가"만 나타낸다. 카테고리는 색이 아니라 **채움 정도**로 구분하므로, 색맹/색약 사용자도 두 카테고리를 구분할 수 있다.

### 공휴일 표시 방식 **[변경]**

공휴일을 날짜 칸 하단의 작은 글씨가 아니라, **일정 칩과 같은 형태의 빨간 막대**로 일정들 사이에 섞어 표시한다. 정렬 시 공휴일이 가장 위 줄을 차지한다.

### 기타

* 모바일 우선, 최대 폭 460px 기준의 단일 컬럼
* 일정 등록까지 최대 2~3번의 사용자 행동으로 완료
* 본문 서체는 한글 가독성이 좋은 산세리프 (Pretendard 계열, 실패 시 시스템 서체)

### DB 함수 **[v3 신규]**

| 함수 | 역할 |
|---|---|

## 6. 배포 구조와 보안 **[v3]**

### 배포 구조

| 역할 | 서비스 | 비용 |
|---|---|---|
| 데이터베이스 | Supabase (Region: Seoul) | 무료 플랜 |
| 호스팅 | Netlify (폴더 하나) | 무료 플랜 |

* Supabase 무료 프로젝트는 일주일간 요청이 없으면 일시정지된다. 데이터는 보존되며 대시보드에서 재개할 수 있다
* Netlify는 새로 올리면 사이트 전체가 교체되고, 이전 배포는 기록으로 남아 되돌릴 수 있다

#### 배포 폴더 구성 **[v3.1]**

홈 화면 아이콘은 실제 이미지 파일을 가리켜야 하므로, HTML 한 개가 아니라 폴더 단위로 배포한다.

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 본체. 사이트 주소(`/`)로 접속하면 열린다 |
| `apple-touch-icon.png` | iOS 홈 화면 아이콘 (180×180) |
| `icon-192.png` / `icon-512.png` | 안드로이드 홈 화면 아이콘 |
| `favicon.png` | 브라우저 탭 아이콘 |
| `manifest.webmanifest` | 안드로이드에서 주소창 없이 실행되도록 하는 설정 |

> **아이콘을 HTML에 넣지 않은 이유**
> 이미지를 HTML 안에 문자열로 심는 방법(data URI)이 iOS 홈 화면 아이콘에서 동작하는지 확인하지 못했다. 실제 파일로 두는 방식은 확실히 동작하므로 그쪽을 택했다.

> **사이트 주소**
> 배포 주소는 루트(`https://<사이트>.netlify.app/`)다. 초대 링크도 이 주소를 기준으로 만들어지므로, 앞으로 주소를 바꾸면 이미 보낸 초대 링크와 홈 화면 바로가기가 모두 끊긴다.

> **이미 추가한 바로가기**
> iOS는 홈 화면에 추가할 때 아이콘을 저장한다. 이미 추가해 둔 바로가기는 아이콘이 바뀌지 않으므로, 지우고 다시 추가해야 새 아이콘이 적용된다.

### 동기화

* 그룹을 열고 있는 동안 20초마다 다시 불러온다
* 앱이 다시 화면에 보일 때(다른 앱에서 돌아올 때) 즉시 다시 불러온다
* 동시 수정 시 마지막 저장이 우선한다

### 보안 수준 — 정확한 설명

앱은 Supabase의 공개 키(anon key)로 DB에 접속하며, 이 키는 HTML 안에 들어 있어 누구나 볼 수 있다.

| 데이터 | 보호 수준 |
|---|---|
| 복구 코드 | **DB 단계에서 보호.** 직접 조회/변경 불가. 정확한 코드를 넣었을 때만 해당 계정을 반환 |
| 그룹장 규칙 (내보내기 / 넘기기 / 이름 변경) | DB 함수가 규칙을 검사하지만, **요청자가 누구인지는 앱이 보내는 값을 그대로 믿는다.** 즉 조작된 요청은 막지 못함 |
| 대리 등록 **[v3.1]** | DB 함수를 거치지 않는 일반 저장이므로 **화면 단계에서만** 그룹장으로 제한된다 |
| 그룹/일정/멤버 | **화면 단계에서만 보호.** 개발자 도구를 다룰 줄 아는 사람은 코드 없이도 모든 그룹의 데이터를 조회/수정할 수 있다 |

> **v2 설계서의 표현 정정**
> v2에서는 "그룹 코드를 아는 사람은 누구나 캘린더를 볼 수 있다"고 적었으나, 실제로는 위 표와 같이 **앱 주소를 아는 사람이면 기술적으로 모든 데이터에 접근 가능**하다. 가족/친구용으로는 현실적인 위험이 낮지만, 민감한 내용은 일정에 적지 않는다.

> **보안을 강화하려면**
> 카카오 로그인 등 실제 인증을 도입하면, DB가 요청자를 직접 확인할 수 있어 "내 그룹의 데이터만 조회", "그룹장만 내보내기"를 DB 단계에서 강제할 수 있다 (9장 남은 과제).

## 8. 구현 원칙

1. MVP에 필요한 기능만 구현한다.
2. 복잡한 기술을 사용하지 않는다.
3. 모바일에서 사용하기 편한 UI를 우선한다.
4. 기능을 하나씩 구현하고 각 기능이 정상적으로 동작하는지 확인한다.
5. 사용자가 별도로 결정해야 하는 사항이 없다면 일반적인 웹앱 개발 관행에 따라 합리적인 결정을 내린다.
6. 향후 기능 확장을 고려하되 MVP에 불필요한 기능은 구현하지 않는다.
7. **[추가]** 저장 실패는 조용히 넘기지 않고 실제 오류 내용을 사용자에게 보여준다.
8. **[추가]** 중요한 데이터를 저장한 뒤에는 다시 읽어 저장 성공 여부를 확인한다.
9. **[추가]** 외부 데이터로 교체될 가능성이 있는 값은 조회 함수 하나로 감싸 접근한다. (공휴일 등)
10. **[v3]** 여러 단계로 이뤄진 데이터 변경(멤버 제거 + 일정 삭제 등)은 DB 함수 하나로 묶어 원자적으로 처리한다.
11. **[v3]** 되돌릴 수 없는 동작(내보내기, 나가기, 그룹 삭제, 로그아웃)은 반드시 확인 창을 거친다.
